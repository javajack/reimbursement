# B2B multi-tenant company onboarding and configuration design for expense/approval workflow tools (evidence base for an India-first employee-reimbursement SaaS, v2 dossier)

## Executive Summary

Across Zoho Expense, Concur, Fyle, Keka, Ramp and ApprovalMax, three approval-configuration paradigms dominate: per-user org-graph pointers (Zoho's "Submits To" / "Approves and Forwards To"), ordered rule stacks with an immovable fallback rule (Fyle), and amount/limit-based Delegation-of-Authority routing (Concur's level-based vs limit-based authorized approvers). The most instructive failure modes are documented in vendor KBs: Zoho hard-blocks submission when a claim matches no approval flow ("does not match your organization's approval criteria"), Concur reports get stuck with "Missing the required approver for next workflow step," and SAP KB 1944022 shows a self-approval deadlock (manager routed to themselves) that requires a support ticket to fix — so a v2 product should ship an always-matching fallback rule, cycle detection on save, prevent-self-approval-with-skip-up default, and a "simulate this claim" tester (precedent: Oracle Fusion's Test Rules > Simulate against real transactions). For mid-flight policy changes, the industry pattern is snapshot-at-submission (Ramp: "Changes to approval workflows only apply to new requests, not those already in progress") with explicit admin-triggered restart (ApprovalMax) and workflow version history. Onboarding benchmarks argue for radical defaulting: median SaaS time-to-value is ~1.5 days, median activation 37%, and onboarding checklists average only 19.2% completion, so the wizard must get a first claim submitted in one session with preloaded categories, a size-based approval template, and everything else (GST, branches, bank file format, employee import) deferred to a checklist. Zoho's own onboarding (quick org setup, default categories, ZIA nudges, free 2-hour Jumpstart) and Fyle's invite flow (bulk Excel template, auto-invite emails, 24-hour links, Pending state, resend) are the closest concrete templates. India-specific config that must exist but can default: GSTIN optional at signup, INR + Apr–Mar fiscal year, branch entities each carrying their own GSTIN (Zoho supports up to 200 branches). Concur's configuration reputation supplies the differentiation story: G2/Capterra reviewers describe back-end configuration as consultant-dependent and "clunky... completed in an odd way that takes longer than you think it should," validating "first claim in 15 minutes, no consultant" as the wedge.

## Findings

- **Zoho Expense custom approvals support up to 10 sequential levels and up to 10 trigger criteria combined with AND/OR logic; criteria include Report Total, Reimbursable Total, Project, Policy Violation count, and report Owner, and admins assign a priority number when a report matches multiple flows ('approval flow with priority number 1 will be prioritized').** _(high)_
  Zoho FAQ: 'you can add up to 10 levels of approval'; help doc lists trigger criteria and 'set up to 10 criteria' with AND/OR; approver-selection options are Submits To, manual user, Project Head, Department Head, Designation-Hierarchy, and lookup custom fields; config path is Admin View > Settings > Modules > [module] > Approvals tab > + New Custom Approval.
  - src: https://www.zoho.com/us/expense/kb/admin/approvals/multi-stage-approvals/  |  https://www.zoho.com/us/expense/help/configuring-approvals/
- **Zoho's default (non-custom) approval is org-graph-driven via two per-user pointers: 'Submits To' (who receives the user's reports) and 'Approves and Forwards To' (next hop for users with approval permission) — the chain is stored on each user record, not in a central matrix.** _(high)_
  Zoho FAQ: 'all the reports, trips, and advances will be submitted to the approver selected under the Submits To dropdown'; secondary hop configured via 'Approves and Forwards To'; set under Admin > Users when creating/editing a user.
  - src: https://www.zoho.com/us/expense/kb/admin/approvals/hierarchical-approval-flow/
- **Orphan-claim failure mode is real and user-blocking in Zoho: if a submitted report matches no configured approval flow, the employee gets a hard error and cannot submit until an admin edits the flows.** _(high)_
  Documented error text: 'You cannot submit this expense report as it does not match your organization's approval criteria. Please contact your administrator to update the approval flow' — Zoho's KB states only the admin can resolve it by modifying approval criteria.
  - src: https://www.zoho.com/us/expense/kb/reports/approval-criteria-error/
- **Concur has the mirror-image failure mode: reports stuck mid-workflow with 'Missing the required approver for next workflow step. You may be able to select an approver; otherwise contact your Expense administrator for assistance,' typically caused by department/cost-object routing not matching the employee; fallback is a default approver, else the user must hand-pick from all approvers.** _(medium)_
  Multiple SAP Concur Community threads ('No Approvers defined in workflow', 'trying to submit an expense report', 'Concur Approval Workflows') describe the error, root causes (employee not in required department; 'workflow may not have been created correctly... can cause issues for multiple users'), and admin fix via Administration > Company > User Administration > Expense Settings.
  - src: https://community.concur.com/t5/Concur-Expense/No-Approvers-defined-in-workflow/m-p/22769  |  https://community.concur.com/t5/Concur-Expense-Forum/trying-to-submit-an-expense-report/m-p/18830  |  https://community.concur.com/t5/Concur-Expense-Forum/Concur-Expense-Approval-workflow/m-p/24804
- **Concur formalizes Delegation-of-Authority two ways: level-based approval (fixed N steps) and limit-based authorized approvers, where each approver gets a currency+amount authority and routing walks the cost-object hierarchy until it reaches an approver whose limit >= report amount; a 'Direct Approval' variant jumps straight to the first approver with sufficient limit, skipping intermediates.** _(medium)_
  SAP Learning (Concur Expense Standard for Administrators) 'Managing a Limit-Based Approval' / 'Managing a Level-Based Approval': 'stops when it reaches an approver who has an approval limit equal to or greater than the cost object amount'; Authorized Approvers Setup Guide: 'Under the Approver Limit section, you set the currency and the amount the Approver can approve within their authority.'
  - src: https://learning.sap.com/learning-journeys/getting-started-with-concur-expense-standard-for-administrators/managing-a-limit-based-approval  |  https://learning.sap.com/learning-journeys/getting-started-with-concur-expense-standard-for-administrators/managing-a-level-based-approval  |  https://community.concur.com/marav43842/attachments/marav43842/ConcurExpense/32457/1/EXP_SG_Workflow_AuthAppr.pdf
- **Concur's admin/configuration complexity is its best-documented weakness: G2's AI-summarized pros/cons say configuring policies, approval flows and integrations 'typically need[s] the expertise of trained administrators or consultants,' and Capterra reviewers give verbatim quotes like 'Concur is often a bit clunky to use on the back end... while it's customizable for our needs, its completed in an odd way that takes longer than you think it should' and 'For one simple trip, it literally takes 3+ hours to input your receipts, input all of the nitpicky data and deal with admin complaints.'** _(medium)_
  G2 pros-and-cons synthesis (admin setup needs trained admins/consultants; 'customization options often require admin involvement, which makes simple changes feel more complex than they should'); Capterra verified-review quotes surfaced in search of capterra.com/p/380/Concur-Expense/reviews; Navan's review roundup of G2 (4/5, 7,000+ reviews) and Capterra (4.3/5, 2,000+ reviews) describes multi-country rollouts as 'lengthy, service-intensive undertaking[s]' extending 'over several months.' Note: G2/Capterra pages block fetch, so quotes come via search snippets.

- **Self-approval deadlock is an enterprise-documented failure mode: in SAP expense approval, when the submitting manager is themselves the cost-object approver and self-approval is disallowed, the approval task routes to the manager who cannot act on it; the documented fixes are a per-employee 'Alternative Approver for Expense Reports' setting or a backend change (via SAP Support ticket) to route to the next-level line manager.** _(high)_
  SAP KB 1944022 'Default Approver Determination for Expense Reports from Managers - Self-Approval is Not Allowed' describes the conflict and three backend routing options (reporting line manager; standard-with-exception escalating to 'the line manager of the cost center manager'; hybrid).
  - src: https://userapps.support.sap.com/sap/support/knowledge/en/1944022
- **Even purpose-built self-approval guards regress: Expensify had a paid ($500 bounty) bug where 'Admin can submit and approve their own report when Prevent Self-Approval is on' — separation-of-duties must be enforced server-side and regression-tested, not just hidden in UI.** _(high)_
  Expensify/App GitHub issues #36425 and #55845 (Approvers Flow — admin can submit expense to self when forbidden); Expensify workspace docs describe the Prevent Self-Approval rule.
  - src: https://github.com/Expensify/App/issues/36425  |  https://github.com/Expensify/App/issues/55845  |  https://help.expensify.com/articles/new-expensify/workspaces/Workspace-Rules
- **Ramp's modern rule-builder abstracts approvers as roles, not names: steps can target 'Any admin', manager, manager's manager, department owner, location owner, custom approval groups, or a specific person, with per-step 'Require all' (AND) vs 'Require any' (OR) logic; its 'Separation of Duties' toggle removes a requester who appears in their own chain and substitutes admin approvers.** _(high)_
  Ramp support doc 'Setting up spend request approvals': approvals workflow builder under Policy tab; threshold gotcha documented ('the dollar amount that is entered is based on annual spend').
  - src: https://support.ramp.com/hc/en-us/articles/20843280013459-Setting-up-spend-request-approvals
- **Mid-flight change semantics converge on snapshot-at-submission: Ramp states 'Approval flows are set at the time a spend request is submitted. Changes to approval workflows only apply to new requests, not those already in progress'; ApprovalMax requires an explicit admin action ('Restart the workflow') to apply new settings to not-yet-approved requests, resetting prior approvals, and keeps a workflow version history; Fyle rule edits take 2–5 minutes to propagate and apply to unreported (not yet submitted) expenses.** _(high)_
  Ramp support doc quote; ApprovalMax Help Centre articles on applying workflow changes to not-yet-approved requests and workflow version history (Xero/stand-alone); Fyle help: reorder/edit 'requires 2-5 minutes to process across unreported expenses.'

- **Fyle's approval engine is an ordered rule stack with a guaranteed fallback: 'All orgs have a default approval rule to add primary approver to all expenses. This rule cannot be modified but it can be re-ordered' — approver sequence is determined by drag-and-drop rule order, and rules can target categories, employees, departments, projects or expense conditions, optionally skipping the primary approver.** _(high)_
  Fyle help article 'Approval workflows on Fyle' (Admin Settings > Workflows > Approvals > Add rule / Re-order); per-employee Primary/Secondary approvers set in Admin Settings > Employees, departments can have dedicated approvers, both bulk-uploadable 'by following a predefined template.'
  - src: https://www.fylehq.com/help/en/articles/11129811-approval-workflows-on-fyle  |  https://www.fylehq.com/product/approvals
- **Keka (India HRMS) lets the approval chain live at expense-policy level or per expense category, and adds a distinct final 'Payout approver' role 'who will have the final authority to determine the payout mode for all approved expenses' — a finance gate between approval and disbursement that maps directly to a bank-file-export product.** _(medium)_
  Keka help 'Configuring approval chain at expense category level': category-level chains group expenses by category for routing; config path Org > Expenses & Travel > Policies & Settings > Approval Chain; payout approver acts after the policy/category chain completes.

- **Role design in expense tools is small and fixed at the core with paid extensibility: Zoho ships exactly three non-editable default roles (Submitter, Approver, Admin) with custom roles only on paid plans (cloneable from defaults); Expensify adds an Auditor role that 'can see all reports... view and comment only,' cannot approve or change policy, and can only export manually to CSV; Keka distinguishes global admin, HR manager and Expense manager for approval actions.** _(high)_

## UX Patterns

- Ordered rule-stack with an immovable fallback rule (Fyle): every org has a default 'route to primary approver' rule that cannot be deleted, only re-ordered — structurally prevents orphan claims; contrast Zoho, which blocks submission outright when no custom flow matches. Adopt the Fyle invariant.
- Per-user org-graph pointers ('Submits To' / 'Approves and Forwards To', Zoho): trivially understandable for <100-person companies and imports cleanly from a manager-email CSV column, but each user edit can silently create cycles or dead ends — validate the graph (cycle/orphan detection) on every user save, not at submission time.
- Role-abstracted approver slots (Ramp): chain steps reference 'Manager', 'Manager's manager', 'Department owner', 'Any admin', or named approval groups instead of named people, with per-step Require-all/Require-any — survives employee churn far better than name-based chains.
- Limit-based DoA routing (Concur authorized approvers): give each approver a currency+amount authority; routing walks up until limit >= claim amount, with an optional 'direct approval' jump to the first sufficient approver — expressible as a one-screen grid (approver × limit) instead of N rules.
- Priority numbers for multi-match disambiguation (Zoho): when a claim satisfies several flows, the lowest priority number wins — simple, but admins must see a 'which rule fired and why' trace; pair with simulation.
- Simulate-before-ship (Oracle Fusion 'Test Rules > Simulate'): dry-run rules against a real or synthetic transaction and show the resolved approver chain; gate behind an admin privilege. For v2: a 'Test a claim' button in the approval-matrix editor (pick employee + amount + category → render the chain).
- Snapshot-at-submission for in-flight claims (Ramp): freeze the approval chain when the claim is submitted; policy edits affect only new claims. Pair with ApprovalMax-style explicit 'Restart workflow' for admins who want re-routing (resets given approvals) and a workflow version history showing who changed what.
- Prevent self-approval with skip-up, defaulted ON (Ramp Separation of Duties; SAP KB 1944022 as the cautionary deadlock; Expensify GH #36425 as the regression warning): when the submitter appears in their own chain, auto-substitute next-level manager or admin — enforce server-side and integration-test it.
- Self-serve vacation delegation with chaining and audit trail (Expensify): approvers set their own delegate in account settings, delegates can have delegates, every delegate action is audit-logged, and a persistent 'Return from Vacation' banner ends it; separate 'out-of-office approver' (approval-only) from 'delegate' (full account access) as Zoho does.
- Bulk add via predefined spreadsheet template + auto invite email + 24h-expiring link + Pending state + bulk Resend (Fyle); Zoho switches to a 'Multiple Users' grid UI above 3 invitees — provide both row-grid (3–20 users) and CSV template (20+).
- CSV import as file → map → validate → fix-in-grid → submit, with inline one-click fixes (find/replace, picklist coercion) and dedupe on email + employee ID; an error-resolution step measurably lifts completed activations 50%+ (OneSchema).
- Domain capture / JIT auto-join (WorkOS pattern): verify company domain via DNS TXT through a self-serve flow, then auto-attach any signup with a matching work email to the tenant (policy: auto-join vs request-to-join) — converts employee self-signup into admin-free growth, with dedupe against invited-pending users.
- Demo claim as sandbox (Stripe test-mode / Notion template pattern): pre-seed each new tenant with one sample submitted claim and let the admin approve it during the wizard — first value ('I saw a claim flow through approval') in minutes without real data; tag demo data and offer one-click purge.
- Setup nudge assistant + persistent checklist (Zoho ZIA): post-wizard, a dismissible checklist tracks remaining config (GST, branches, bank format, import) — but expect ~19% completion, so nothing on the checklist may be required for the first claim.
- Category-level approval-chain override plus terminal Payout Approver (Keka): approval chain defaults at policy level, optionally overridden per category, with a final finance role that owns payout mode — maps 1:1 to a 'finance reviewer before bank-file export' stage.
- White-glove escape hatch (Zoho Jumpstart free 2-hour setup; Concur's consultant ecosystem as the anti-pattern): offer free guided setup calls for 200+ employee tenants instead of letting complexity push buyers to consultants.
- Approval-chain preview on the submission screen (Fyle real-time chain visibility): show the employee exactly who will approve before they hit submit — doubles as continuous validation of the matrix and reduces 'where is my claim' support load.
- Workflow copy across entities (ApprovalMax): 'Copy workflow settings' to another organisation/branch — for India multi-GSTIN branches, let one branch's matrix be cloned then diffed.

## Risks / Caveats

- G2, Capterra, TrustRadius and SAP Concur Community pages block direct fetching (403); verbatim Concur complaint quotes were obtained via search-result snippets of those pages and could not be re-verified word-for-word on-page — treat individual quotes as medium confidence and re-verify manually before print.
- OneSchema's CSV-importer cost/benefit numbers ($100K build, 50%+ activation lift) and Userpilot's TTV/activation/checklist benchmarks are vendor-published from their own customer bases; directionally useful, not audit-grade.
- Concur behavior differs across Standard vs Professional editions (e.g., limit-based approval setup paths); the level-based/limit-based description comes from SAP Learning for Standard edition and the Authorized Approvers guide — exact UI may differ per edition and year.
- Darwinbox and parts of Keka admin documentation are login-gated; their workflow capabilities are sourced from marketing pages and help-center search snippets (medium confidence, thin on exact UI labels).
- Userpilot's FinTech activation figure (5%) vs FinTech checklist completion (24.5%) shows benchmark volatility across their reports; use ranges, not point targets, when setting v2 KPIs.
- The ApprovalMax 'Restart the workflow' detail came from a search snippet of a moved KB page (old URLs 404); the collection page is cited but the exact article should be re-located before quoting.
- Zoho's default-role nuance that an Approver 'can approve their own reports' is a control gap by competitor design, not a recommendation — Indian auditors (CARO/internal financial controls) will expect self-approval prevention, which strengthens the default-ON recommendation but was not separately verified against audit guidance in this pass.

## Recommendations

- Recommended onboarding wizard (5 steps, <15 min, everything else deferred): (1) Create account with work email → org name, country=India default, currency INR, fiscal year Apr–Mar prefilled; GSTIN field present but skippable. (2) Pick a company-size template — '<50: single level, claims go to reporting manager'; '50–250: manager → finance, plus amount threshold (e.g., >Rs 25,000 adds finance head)'; '250+: manager → department head over threshold → finance', all editable later. (3) Categories preloaded (India set: Local Conveyance, Travel–Air/Rail, Lodging, Meals, Fuel/Mileage, Telecom, Office Supplies, Software/Subscriptions, Medical, Miscellaneous) with on/off checkboxes only. (4) Invite up to 3 people inline (name, email, manager) or 'skip — import later'. (5) A pre-seeded demo claim appears; admin approves it in-wizard (first value = watching a claim flow). Bank account for payout-file export, GST details, branches and bulk import live on a post-wizard checklist — none block the first claim.
- Hard-require before first REAL claim only three things: at least one admin, a guaranteed-match fallback approval rule (ship it built-in and undeletable, Fyle-style), and at least one active category. Bank details are required before the first PAYOUT RUN, not the first claim — sequence value before compliance chores.
- Build the approval matrix as a rule-builder with role abstractions (Manager, Manager's manager, Department head, Finance, named group) plus an optional one-screen limit grid (approver × max amount, Concur-style) for DoA-minded finance teams; avoid pure org-chart-only chains, but import 'manager email' from CSV to power the Manager role.
- Ship four safety invariants from day one: (a) graph validation (cycles, orphan approvers, deactivated-user references) runs on every user/rule save with inline errors; (b) prevent-self-approval ON by default with automatic skip-to-next-level (cite SAP KB 1944022 deadlock as the why); (c) vacation/out-of-office approver (approval-only, no account access) with optional auto-escalation after N days idle; (d) claims never blocked at submission for routing reasons — worst case routes to admin queue with a 'rule gap' flag.
- Implement 'Simulate a claim' in the matrix editor (pick employee + amount + category + entity → render the exact approver chain and which rule fired), Oracle-style but one click; also show the resolved chain to employees on the submission screen (Fyle pattern).
- Adopt snapshot-at-submission semantics and say so in the UI (copy Ramp's sentence); give admins an explicit 'Re-route in-flight claims to new policy' action that resets approvals (ApprovalMax restart pattern) and keep a who-changed-what version history of policies and matrices.
- Employee import: ship a downloadable CSV template (name, work email, employee ID, department, manager email, branch, role), an in-browser map→validate→fix grid with one-click fixes, dedupe on email + employee ID, and a dry-run preview ('212 will be invited, 3 duplicates skipped, 5 errors'); send invites with 7-day magic links (Fyle's 24h is too aggressive), Pending state, bulk resend. Add domain capture (DNS TXT verification → auto-join policy) so late employees self-onboard without admin work.
- Role set for Phase 1: Admin, Finance (approve + payout-file export + credits purchase), Approver (derived from rules, not assigned), Employee, and a read-only Auditor (view/comment/export-CSV only, Expensify-style) — keep all free per the unlimited-users pricing to make auditor/CA access a differentiator; defer custom roles to paid tiers like Zoho only if needed.
- Per-entity design: model Branch/Entity with its own GSTIN, address, bank account (for separate payout files) and optional approval-matrix override; provide 'copy configuration from existing branch' (ApprovalMax copy pattern) and cap complexity (Zoho's 200-branch ceiling shows even leaders bound this).
- Instrument onboarding against benchmarks: target first demo-claim approved in-session (minutes), first real claim < 24h (beats the 1.5-day median TTV), define activation = 3 events (first real claim submitted, first approval completed, first payout file exported) and expect ~19% checklist completion — so re-nudge via the employee-side soft-paywall nudges and ZIA-style assistant rather than relying on the checklist.
- Weaponize Concur's configuration reputation in positioning and design reviews: every config screen should pass the test 'could an Indian SMB office manager do this without a consultant or support ticket?' — the documented Concur failure modes (stuck 'missing required approver' reports, backend-change-only routing fixes) are the anti-checklist.
