# ADJUDICATIONS — binding cross-page decisions (apply during the fix pass)

Where pages disagreed, these decisions are now CANON (they extend THESIS-V2). Every fix agent must apply the ones touching its page, exactly.

1. **PayoutInstruction.status enum (canon):** `pending → dispatched → paid | failed | cancelled`. payouts.mdx replaces `issued`→`dispatched`, `succeeded`→`paid` everywhere; data-model CHECK becomes ('pending','dispatched','paid','failed','cancelled').
2. **Instruction identity:** instructions are IMMUTABLE attempts. Reissue creates a NEW PayoutInstruction (new `pin_`) on the same claim in a new `building` batch, audit `instruction.reissued` linking old→new. state-machines deletes the failed→pending re-queue transition and any attempt++/batch_id re-pointing language.
3. **in_payout timing:** while a batch is `building`, member claims REMAIN `approved` (reserved; removal releases the reservation). Claims flip to `in_payout` when the batch is exported (file mode) or starts executing (API mode). Fix payouts.mdx prose/truth-table and end-to-end-flow step 11 + master table to match state-machines.
4. **Instruction failure:** the claim HOLDS at `in_payout` in the repair queue. It returns to `approved` only on explicit finance write-off, or batch cancel while building. end-to-end-flow's "back to approved flagged payout_failed" is wrong; "repair queue" is the canonical term.
5. **ApprovalStep SLA semantics:** breach → `escalated` (successor step for backup/delegate/admin with a fresh clock); when the escalation ladder is exhausted without a decision → `expired` (terminal marker; claim parks in the admin queue). state-machines aligns its diagram and transition rows to this (approval-engine/e2e already have it).
6. **Config API surface (canon, per config-schema):** `GET /api/v1/company-config` (current document), `PUT /api/v1/company-config` (whole-document replace with client-supplied last-seen version; `409 CFG_VERSION_STALE`), `POST /api/v1/company-config/validate`, `POST /api/v1/company-config/simulate-claim`, `GET /api/v1/company-config/versions`. spec/api drops `PATCH /company/config/{domain}` and fixes the domain list to: org, categories, policy_tables, approval, credits, payouts, notifications, locale.
7. **Receipt upload protocol (canon, per architecture):** presigned three-step: `POST /receipts` (returns `rcp_` id + presigned PUT URL) → client PUTs the compressed page to storage → `POST /receipts/{id}/complete`. capture-pipeline rewrites its upload section; retry table: storage PUT failures are network-class retryable; 403 on expired presign re-requests a fresh URL via the same `POST /receipts` idempotency key.

The `max(20, 3 × remaining credits)` fair-use scan cap applies only while balance is positive. end-to-end-flow's gate-one paragraph adopts this (credits-and-metering and state-machines already say it).
